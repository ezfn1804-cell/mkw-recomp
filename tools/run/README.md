# tools/run

Game runs and diagnostics of a running `build/mkw`. Output goes to `build/run/` and `scratchpad/`. Heavy commands go
through `job.sh`.

| Script | What it does | Usage |
|---|---|---|
| `job.sh` | Runs a heavy command (a game run, a replay) through the host's job runner when there is one (`JOB_RUNNER`, memory cap and one at a time), else directly | `tools/run/job.sh run\|start NAME CMD...` |
| `watch.sh` | Follows a run's log and prints the lines matching a pattern, plus FATAL and guard stops; exits when the run ends (the command of a Monitor) | `tools/run/watch.sh NAME [PATTERN]` |
| `live.sh` | A run that stays alive to be inspected through its control FIFO (`MKW_CTL`, `runtime/core/base/ctl.c`), with the race runs' settings | `tools/run/live.sh NAME [SECONDS]` |
| `ctl.sh` | Sends a command to that run and waits for its answer: `frame`, `shot PATH` (whole screenshot and `PATH-s.png` 1280 wide for viewing), `dump DIR [ubo|lut]` (dump of the next frame), `flight`, `mem ADDR SIZE PATH` (game memory to a file), `tex ADDR` (textures over that address; 0: pool images larger than their storage), `press <ticks> <button> [hold]`, `stop` | `tools/run/ctl.sh NAME COMMAND...` |
| `at.sh` | `ctl.sh` commands when the game enters one of its phases (`AIGlobalSeq*` nodes: `TitleMenuMain`, `PartsSelectEx`, `SimpleConfirm`, `ReadyRace`, `WaitIntroMovie`…), not at a frame number. The run needs `MKW_SEQ_WATCH=1`; `MKW_SEQ_HOLD=WaitIntroMovie` lets the movie play without the script skipping it | `tools/run/at.sh NAME PHASE [+FRAMES] command [arg] [-- command...]` |
| `flicker.sh` | Counts the frames with a black lower half in the 600 thumbnails up to a frame of a live run (title scene flicker) | `tools/run/flicker.sh NAME [FRAME]` |
| `race.sh`, `press-race.txt` | A run up to the race: A every 90 frames from frame 700, 720p overlay, BC1 off; calls `run_perf.sh`. Exits by itself 20 s (`RACE_SECS`) after the race starts, with phase watching off from there and the `MKW_HOST_TIME` census of that window | `tools/run/race.sh NAME [SECONDS]` |
| `race.sh RACE_TT=1` | Up to a time trial with `MKW_QUICK_RACE=tt` (phase script in `runtime/input/input.c`) (Mario, standard kart, Cheep Cheep Falls, solo): a grid with a single kart 29.6 s after boot. With `MKW_UI_FOCUS=1` the log says which button has the cursor (`ui: focus L_Btn_02`) | `RACE_TT=1 tools/run/race.sh NAME` |
| `ab.py` | A/B inside a run: with `MKW_AB=<s>` blocks A and B alternate (A B B A; B A A B with `MKW_AB_INVERT=1`) from the race start, and a switch `MKW_<X>=ab` only acts in the B blocks; compares the 60-frame windows that are entirely A or entirely B and, with normal and inverted runs, gives the change with the scene balanced. Between two identical runs there is up to 12 ms per frame of noise | `uv run tools/run/ab.py build/run/NAME.log` |
| `run_perf.sh` | `build/mkw` (or another executable with `MKW_RUN_BIN`, e.g. a player folder's) under `perf record` (flat) with a GPU memory cap, and the 40 hottest symbols; opens the control FIFO like `live.sh` (`ctl.sh` and `at.sh` work with `race.sh` too) | `tools/run/run_perf.sh NAME [SECONDS]` |
| `texms.sh` | Total render thread time in texture uploads (and ASTC) up to a frame, from a run's `perf` lines, and the worst frame | `tools/run/texms.sh build/run/NAME.log [FRAME]` |
| `perf_split.sh` | Splits a profile by owner (game code, runtime, drivers) and lists the 15 hottest game functions | `tools/run/perf_split.sh FILE.perf` |
| `kstacks.py` | Where each thread sleeps inside the kernel (stacks of `perf record -e cs -g` with kallsyms names) and the `mmap_lock` waits per thread and call | see its header (kallsyms needs root) |
| `crit_path.py` | Critical path of each frame of an `MKW_CRIT` recording (with `MKW_TRACE=sched`): which thread and which state (running, waiting for a core, host call, wakeup latency) takes each ms between two presents (from totk-pc-recomp, MIT) | `uv run tools/run/crit_path.py FILE.bin` |
| `rqwait.py` | With a run going, CPU and run-queue wait (ready without a CPU) of each `build/mkw` thread over a window of the race, by thread name (`/proc/.../schedstat`): whether a change takes host CPU away from the replay or the render | `uv run tools/run/rqwait.py build/run/NAME.log [--skip 6] [--secs 12]` |
| `locks.py` | Wait on each runtime lock during the race, in ms per second, per lock, per requester and per holder while another waited (`MKW_LOCK_PROF=1`), with `build/mkw`'s names | `uv run tools/run/locks.py build/run/NAME.log` (Windows: `--exe build/dist/windows/mkw.exe`) |
| `perf_sdk.py` | How much CPU the recompiled SDK code takes in a profile, per thread and per namespace (`nn::os`, libc, math…), with `build/bindb.sqlite`'s names | `uv run tools/run/perf_sdk.py scratchpad/NAME.perf` |
| `sample_stacks.sh` | Stack snapshots through gdb when `perf` does not record call graphs (`MKW_ALLOW_PTRACE=1`) | `tools/run/sample_stacks.sh DIR [N] [GAP]` |
| `gpu_ok.sh` | Refuses when amdgpu logged since boot a failed ring reset or a full GPU reset (after a failed reset, the next replay froze the machine); episodes recovered in the ring, however many, let it go on. Called by `live.sh`, `run_perf.sh` and `replay.sh`, which set `MKW_GPU_GUARD=1` | `gpu_ok.sh` |
| `avail.sh` | MB available for a run: `MemAvailable` plus `GPUReclaim` (TTM page pool the kernel releases under pressure); used by the thresholds of `live.sh`, `run_perf.sh` and `replay.sh` | `avail.sh` |
| `memwatch.sh`, `memtop.sh` | RSS, swap, GTT and VRAM every 5 s; memory maps with their Rss after N seconds | `memwatch.sh OUT.tsv`, `memtop.sh AT OUT` |
| `stacks.py` | Stacks of every thread of a running `build/mkw`, with the game's names | see its header |
| `summary.py` | A log summed up in ~15 lines: how it ended, last frame and phases, median and p95 frame time before and during the race, VRAM peak, `MKW_HOST_TIME` census, grouped failures and the game speed (a warning when the race runs in slow motion) | `uv run tools/run/summary.py build/run/NAME.log [...]` |
| `diagnose.py` | Standalone, read-only numeric timing report for Windows testers, excluding raw log paths/assets; also checks the local decrypted dump's structure and 1.0.0 build id (not its completeness). See [the custom version guide](../../docs/custom-version.md) | `python diagnose.py LOG [--out NEW_REPORT.txt]` or `python diagnose.py --check-game DIR` |
| `collect-diagnostic.cmd` | Double-click export of an existing game's `logs/mkw.log` with the port's bundled Python; copy beside `mkw.exe` with `diagnose.py`. Does not launch the game, setup or updater | double-click, or drag a `.log` onto it |
| `gpucmp.py` | The race's GPU time of several runs side by side: median `gpu avg` and interval per 60-frame window in the race, whole `MKW_PASS_TIMING=1` windows in the race (busy and the largest pass) and the last texture memory; for changes without an in-run switch (`MKW_ASTC_BC1`) | `uv run tools/run/gpucmp.py build/run/NAME.log [...]` |
| `why.sh` | Sourced by `run_perf.sh` and `live.sh`: under Claude Code (`CLAUDECODE=1`) a run without `MKW_RUN_WHY` (what I expect to see and what I conclude from each result) is refused and the captures of `build/cap` are suggested; each reason goes to `build/run/why.log` | `MKW_RUN_WHY="…" tools/run/race.sh NAME` |
| `kwin-rule.sh` | KWin rule for our runs' windows (app id `mkw-recomp-run`, `MKW_BACKGROUND_WINDOW=1`): they never take the focus and open below the others; the player's window is not touched | `tools/run/kwin-rule.sh [--remove]` |
| `wine.sh` | An `.exe` (`build/mkw.exe`, a self-test) in Wine with its own prefix in `build/win/wineprefix`, without Mono or Gecko: it shows no dialogs and does not touch `~/.wine`. Its `Desktop` is your desktop folder (Wine links it in every new prefix): what a test creates on the desktop (a `.lnk`) is deleted by hand | `tools/run/wine.sh PROGRAM.exe [ARGS...]` |
| `envs.py` | Catalogue of the `MKW_*` variables the runtime reads (`cfg_get` and `rt_knob`): where and their comment, taken from the code | `uv run tools/run/envs.py [REGEX]` |
| `sym.py` | Names the `build/mkw` addresses of the log (`exe+`, `mkw+`, base 0x200000) and, for translated code, its game function | `uv run tools/run/sym.py DIR...` or `< build/run/NAME.log` |
