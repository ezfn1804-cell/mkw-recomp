# tools/prepare

| Script | What it does | Usage |
|---|---|---|
| `prepare.py` | Prepares the game in the executable's folder from the player's copy: checks it is 1.0.0 (`main`'s build id, RomFS files), copies `exefs/` and copies or links `romfs/` (`mkw.ini`), generates the C, builds it into `mkwgame.so`/`mkwgame.dll` with zig (or clang), translates the shaders to `spirv/` (as many processes as cores fit in free memory, 0.75 GB each; half as many again if one dies, issue #24) and starts the game for a minute (no focus, no sound, with a separate profile) to leave the pipeline cache and its list ready for the first game. The internal resolution is not a step: it is the `MKW_RESOLUTION` option (`runtime/sdk/fs/romfs_res.c`). One event per output line (`step`, `progress`, `skip`, `done`, `error`) for the start screen; each step saves its key in `setup-state.json` and an interrupted setup resumes after the last step done. On Windows the link is `zig lld-link` with the package's prebuilt C runtime (`machine.py` `crt_link`): zig never builds its libc on the player's PC, the build that never ended on many of them (issue #2). The tools' output and the timings (zig's first link, the link) go to `logs/setup.log`; a link over 30 min stops with an error | From the start screen (Game files → Prepare); by hand: `python prepare.py --source DIR --game DIR [--romfs copy\|link]`; without `--source`, the last setup's copy and mode (after an update) |
| `update.py` | The start screen's update, from `ezfn1804-cell/mkw-recomp` by default: `check` finds newer published releases, ordering `custom.N` numerically; custom builds also accept published custom prereleases. Drafts and Actions artifacts are excluded. `fetch` downloads exactly the offered tag, requires and verifies GitHub's SHA-256, and restricts Windows ZIP entries to runtime/setup files. The launcher swaps these with rollback (`runtime/ui/launcher/launcher_update.cpp`). `clean` removes only the distributed files' `*.old` backups. TLS: the system's CA store, else pip's bundled one | From the start screen; by hand: `python -I update.py check --version 0.1.8-custom.2`, `fetch --tag vX --dest DIR`, `clean --game DIR`; `MKW_UPDATE_REPO` overrides the repository |
| `machine.py` | What `prepare.py`'s steps run with: the package's tools (`setup/` next to the executable) or the system's, the tool processes tied to the setup's (process group, Windows job object), and the memory that sizes the parallel jobs | Imported by `prepare.py` |
| `plan.py` | Content fingerprints for the generator, compile recipe/toolchain, shader modules and warm-up; runtime-only updates preserve the compiled game and shaders. Missing libraries/identity files recover cleaned sources; interrupted objects resume only with matching inputs. Packaged tool/CRT input stamps avoid recompiling for incidental runner paths. Old states retain assets and rebuild unverifiable derived output once. RomFS file contents are not integrity-checked; the supported source remains the unmodified 1.0.0 dump | Imported by `prepare.py`; checked by `tests/test_incremental.py` |
